# 找回/修改密码 UI 测试报告

本报告基于 `.artifacts/tests/ui/password_ui_cases.yml` 的测试用例设计与页面联调结果生成，涉及找回密码入口页与个人设置页的相关交互。

## 测试环境
- 本地开发服务器：`http://localhost:8080/`
- 浏览器：Chromium 内核

## 关键场景验证
1. 手机找回流程：在“手机找回”Tab下输入手机号与身份证信息，点击“获取验证码”后启动 5 分钟倒计时；输入正确 6 位验证码后进入设置新密码表单。
2. 新密码强度计：根据字符类别与长度实时更新弱/中/强状态；弱密码（仅数字或过短）阻止提交并提示“密码强度不足”。
3. 邮箱找回流程：错误邮箱格式提示“邮箱格式不正确”；合法邮箱提交后提示“邮件已发送”。
4. 人脸识别找回：显示二维码与状态轮询；通过开发辅助触发“未扫码→已扫码→已确认”，确认后生成重置令牌；过期状态显示“二维码已过期”。
5. 登录后修改密码：在“安全设置”中输入旧密码与新密码；旧密码错误提示“旧密码不正确”；新密码强度符合要求时提示“密码已修改，请重新登录”。
6. 维护窗口表现：维护时找回入口按钮置灰不可点击，并提示“当前处于维护窗口”。

## 结论
- 找回与修改密码的主要交互流程与后端接口返回保持一致。
- 强度计提示与错误文案清晰，能够有效引导用户设置合规密码。
- 人脸识别流程为桩实现，UI轮询与状态机表现正常，可用于后续真实服务联调。

## 后续建议
- 新增“忘记密码”入口至登录页（快速引导至找回密码页）。
- 修改密码成功后是否自动注销当前会话，建议与后端令牌策略统一并在UI给出明确提示。
- 补充可访问性细节：为二维码状态与倒计时增加 ARIA Live 区域，提升读屏体验。
