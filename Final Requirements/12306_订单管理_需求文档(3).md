## 1. 功能概述 (Feature Overview)

### 1.1 业务流程描述

订单管理功能覆盖从车票查询、预订、订单填写到订单管理的完整业务流程：

```
用户登录 → 车票查询 → 选择车次 → 点击预订 → 选择乘车人 → 选择席位 → 提交订单 → 订单管理 → 支付/取消订单
```

**流程详解**：

1. **车票查询阶段**
   - 用户在首页输入出发地、目的地、出发日期
   - 系统展示符合条件的车次列表
   - 用户可通过筛选条件（发车时间、车次类型、席别等）优化查询结果

2. **预订阶段**
   - 用户点击目标车次的"预订"按钮
   - 系统跳转至订单填写页面

3. **订单填写阶段**
   - 用户选择乘车人（从常用联系人列表）
   - 系统显示选座页面，用户选择具体座位
   - 系统锁定座位并生成待支付订单

4. **订单管理阶段**
   - 用户进入"未完成订单"页面
   - 可查看订单详情（车次、乘客、席位、价格）
   - 可选择"去支付"或"取消订单"

### 1.2 子功能列表

#### 1.2.1 车票查询子功能
- 出发地/目的地选择（支持中文输入和联想）
- 日期选择（日历控件）
- 单程/往返切换
- 普通票/学生票切换
- 车次列表展示（包含余票信息、价格、时刻表）
- 高级筛选（发车时间段、车次类型、出发/到达车站、席别）
- 显示折扣车次/积分兑换车次/全部可预订车次切换

#### 1.2.2 订单填写子功能
- 常用联系人选择（支持多人）
- 席别选择（商务座、一等座、二等座等）
- 选座功能（可视化座位图）
- 车次详情展示
- 票价计算和展示
- 提交订单

#### 1.2.3 订单管理子功能
- 订单分类查看（未完成订单、未出行订单、历史订单）
- 订单详情展示
- 取消订单（带二次确认）
- 去支付（跳转支付页面）
- 订单中心导航（火车票订单、候补订单、计次定期票等）

### 1.3 功能边界

**支持的功能**：
- ✅ 车票查询与筛选
- ✅ 在线预订车票
- ✅ 多乘车人订票
- ✅ 自选座位
- ✅ 订单查看与管理
- ✅ 订单取消

**不支持的功能**：
- ❌ 改签功能（需在订单详情中单独操作）
- ❌ 退票功能（需在订单详情中单独操作）
- ❌ 积分兑换（本次探索未涉及）
- ❌ 候补订单（单独功能模块）
- ❌ 实际支付（需要支付密码和银行卡信息）

### 1.4 前置条件

- **必须登录**：所有预订和订单管理功能均需用户登录
- **实名认证**：乘车人必须完成实名认证（居民身份证等有效证件）
- **添加常用联系人**：至少有一个常用联系人信息
- **网络环境**：稳定的网络连接
- **浏览器要求**：支持现代浏览器（Chrome、Edge、Firefox等）

## 2. 优先级 (MoSCoW评级)

### 2.1 Must Have（核心功能）

| 功能点 | 评级依据 |
|--------|----------|
| 车票查询 | 核心入口功能，无此功能无法开始预订流程 |
| 车次列表展示 | 必须展示可用车次和余票信息，否则用户无法选择 |
| 预订按钮 | 唯一进入订单填写页的入口，缺失则流程断裂 |
| 乘车人选择 | 订票必须指定乘车人，实名制要求 |
| 席位选择 | 必须选择席别和具体座位才能生成订单 |
| 提交订单 | 生成待支付订单的关键步骤 |
| 订单详情展示 | 用户必须能查看订单信息才能决定后续操作 |
| 取消订单 | 用户反悔或误操作时的必要功能，避免资源浪费 |

### 2.2 Should Have（重要功能）

| 功能点 | 评级依据 |
|--------|----------|
| 单程/往返切换 | 显著提升用户体验，减少重复操作 |
| 车次类型筛选 | 帮助用户快速找到目标车次，提升效率 |
| 发车时间筛选 | 常用筛选条件，影响用户体验 |
| 席别筛选 | 用户根据预算和需求筛选车次的重要工具 |
| 显示折扣车次 | 帮助用户节省费用，提升满意度 |
| 订单分类（未完成/未出行/历史） | 便于用户管理不同状态的订单 |
| 取消订单二次确认 | 防止误操作，保护用户权益 |
| 温馨提示信息 | 告知用户重要规则和时间限制 |

### 2.3 Could Have（增强功能）

| 功能点 | 评级依据 |
|--------|----------|
| 学生票切换 | 针对特定用户群体的优惠功能 |
| 显示积分兑换车次 | 会员增值服务，有助于提升忠诚度 |
| 显示全部可预订车次 | 提供更多选择，但可能降低页面加载性能 |
| 出发/到达车站筛选 | 针对大城市多车站场景的细分需求 |
| 复兴号/智能动车组筛选 | 针对偏好特定列车类型的用户 |
| 车次停靠站信息 | 帮助用户了解列车运行路径 |

### 2.4 Won't Have（当前版本不考虑）

| 功能点 | 评级依据 |
|--------|----------|
| 改签功能 | 属于独立业务模块，本次需求不涉及 |
| 退票功能 | 属于独立业务模块，本次需求不涉及 |
| 支付功能 | 涉及第三方支付接口，本次仅探索到订单生成 |
| 候补订单 | 独立功能模块，有单独入口 |
| 餐饮订购 | 独立功能模块，不属于核心订单流程 |

## 3. 用户故事 (User Stories)

### 3.1 车票查询相关

> **说明**：车票查询功能的详细用户故事已在《12306_车票查询_详细需求文档.md》中完整描述。此处仅列出与订单管理流程直接相关的核心场景。

#### US-01: 查询并选择车次（订单入口）

```
As a 已登录用户
I want to 查询车次并点击预订按钮
So that 我可以开始创建订单

验收条件：
- 能成功查询出符合条件的车次列表
- 有余票的车次显示"预订"按钮
- 点击"预订"按钮后跳转到订单填写页
```

### 3.2 预订相关

#### US-02: 预订车票

```
As a 已登录用户
I want to 点击车次列表中的"预订"按钮
So that 我可以开始填写订单信息

验收条件：
- 每个有余票的车次都有"预订"按钮
- 点击后跳转到订单填写页
- 订单填写页显示所选车次的详细信息
- 如余票不足，按钮显示为灰色或无
```

#### US-03: 选择乘车人

```
As a 已登录用户
I want to 从常用联系人列表中选择乘车人
So that 我可以为自己或他人订票

验收条件：
- 页面显示所有已添加的常用联系人
- 每个联系人显示姓名、证件类型、证件号部分信息
- 可通过复选框选择一个或多个乘车人
- 选择后乘车人信息显示在右侧订单汇总区
- 如弹出温馨提示，能正常关闭
```

#### US-04: 选择座位

```
As a 已登录用户
I want to 从可视化座位图中选择具体座位
So that 我可以坐在自己偏好的位置

验收条件：
- 页面显示该车厢的座位布局图
- 不同类型的座位有不同标识（A-F列）
- 靠窗座位有特殊标注
- 点击座位后座位被选中（视觉反馈）
- 点击"确认"后返回订单页并显示所选座位号
```

### 3.3 订单管理相关

#### US-05: 查看未完成订单

```
As a 已登录用户
I want to 进入订单管理页查看未完成订单
So that 我可以继续支付或取消订单

验收条件：
- 能从个人中心导航到"火车票订单"
- 默认显示"未完成订单"标签页
- 订单显示：车次信息、乘客信息、席位、价格、状态
- 显示订票日期
- 显示"取消订单"和"去支付"按钮
- 显示温馨提示（支付时限、规则说明）
```

#### US-06: 取消订单

```
As a 已登录用户
I want to 取消未支付的订单
So that 我可以释放席位并重新选择

验收条件：
- 点击"取消订单"按钮后弹出确认对话框
- 对话框提示取消规则（一天内3次限制）
- 点击"确定"后订单被取消
- 显示"取消订单成功"提示
- 页面返回车票查询页或订单列表刷新
```

### 3.4 异常流程

#### US-07: 无余票情况

```
As a 已登录用户
I want to 看到无余票车次的明确提示
So that 我不会浪费时间尝试预订

验收条件：
- 无余票的席别显示"--"或"无"
- "预订"按钮不可点击或不显示
- 可能显示"候补"按钮（如支持候补）
```

#### US-08: 未登录访问

```
As a 未登录用户
I want to 查看车次列表但无法预订
So that 我知道需要登录才能继续

验收条件：
- 可以查询车次列表
- 点击"预订"按钮后跳转到登录页
- 登录后能继续原操作
```

## 📊 探索过程总结

### 探索路径

1. **车票查询页** → 输入查询条件 → 展示车次列表 → 应用筛选
2. **预订流程** → 点击预订 → 选择乘车人 → 选择席位 → 提交订单
3. **订单管理** → 查看未完成订单 → 点击取消订单 → 确认取消 → 返回查询页

### 关键发现

1. **登录状态必需**：所有预订操作都需要用户已登录
2. **温馨提示弹窗**：选择乘车人后会弹出温馨提示，需要确认才能继续
3. **座位可视化**：选座功能提供车厢座位布局图，用户体验良好
4. **取消限制规则**：一天内最多取消3次订单，超过则无法继续购票
5. **自动跳转机制**：取消成功后自动返回车票查询页，释放预订限制
6. **实时余票更新**：车次列表实时显示各席别余票数量

### 技术特点

- **前端技术**：使用大量JavaScript进行动态交互
- **无障碍支持**：页面提供无障碍模式和敬老版入口
- **安全机制**：会话管理、实名认证、防止重复提交
- **性能优化**：分页加载、异步查询、缓存常用数据

### 改进建议

1. **用户体验**：
   - 建议增加订单填写进度条，告知用户当前步骤
   - 建议在选座页提供"自动选座"选项，加快流程
   - 建议在取消订单时显示剩余可取消次数

2. **功能增强**：
   - 建议支持订单暂存功能，允许用户稍后继续填写
   - 建议增加"推荐车次"功能，根据用户历史优先推荐
   - 建议增加价格变动提醒，用户订阅后票价下降时通知

3. **错误处理**：
   - 建议增加网络不稳定时的自动重试机制
   - 建议在并发冲突时自动推荐相邻座位
   - 建议在会话即将超时前弹出提醒，避免操作丢失
